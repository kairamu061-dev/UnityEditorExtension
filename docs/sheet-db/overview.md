# sheet-db 概要

パッケージ: `com.obelune.sheet-db`（名前空間 `Obelune.SheetDb`）

## 目的・背景

ゲームのデータ（アイテム・敵・スキルなど）を、Excel のブック（xlsx）にリレーショナルデータベースとして置く。
テーブル同士は ID で参照し合い、参照はブックをまたぐ。データは最終的に万単位の行になる。

Excel は表を編集する道具としては優れているが、次のことが苦手である。

- ブックをまたいで、参照先の行を辿ること（「このアイテムのカテゴリは何か」「このカテゴリを使っているアイテムはどれか」）
- 参照が切れている・ID が重複している、といった壊れ方に気づくこと
- 何十冊ものブックを横断して検索すること

この機能は、Unity エディタの中でデータベース全体を**素早く参照・検索・検査**できるようにする。編集は Excel で行い、Unity は保存された内容をすぐに反映する。

## スコープ

### 作るもの

- 指定したフォルダの xlsx を読み、シートを「テーブル」として扱う読み込み処理（外部ライブラリを使わない）
- 見出しの行に書いた型と参照の定義（スキーマ）の解釈
- テーブル・行の一覧、検索、参照先へのジャンプ、参照元の一覧を備えた EditorWindow
- 参照切れ・主キーの重複・型の不一致を一覧にする検査
- 読み込み結果のキャッシュ（`Library/`）。変わったブックだけを読み直す
- xlsx が保存されたら、エディタに戻ったときに反映する仕組み
- 規模の目標を測るための、合成データの生成と所要時間の計測

### 作らないもの

- Unity からの編集・xlsx への書き戻し（正本は xlsx。編集は Excel で行う）
- ランタイム（ビルドしたゲーム）からの読み込み・書き出し（`docs/project_overview.md` の方針どおり。必要になったら、この機能エリアで改めて決める）
- 数式の再計算（xlsx に保存された計算結果を使う）
- xls（旧形式）・csv・Google スプレッドシートの読み込み
- 複数のテーブルを結合して見せるクエリ言語

## 制約

- **外部パッケージに依存しない**（`docs/project_overview.md`）。xlsx は BCL の `System.IO.Compression` と `System.Xml` だけで読む。.NET Standard 2.1 と .NET Framework の両方の API 互換レベルで、追加の設定なしにコンパイルでき、読めることを**測った**（`dev-notes.md`）
- 数式のあるセルは、xlsx に保存されている計算結果を読む。計算結果が保存されていないブック（Excel 以外の道具で作ったものなど）では、そのセルは「値なし」になる
- xlsx は zip なので、git では差分もマージもできない。**同じブックを複数人が並行して編集しない**運用が前提になる。テーブルをどのブックに置くかは、編集する人の分担に合わせる
- Excel は、開いているブックの隣に `~$<名前>.xlsx` という一時ファイルを作る。読み込みでは無視する
- 規模とレスポンスの目標（`spec.md` の「性能の目標」）を満たすこと。目標は合成データで測る

## 完了条件

- `spec.md` の機能一覧のすべてについて、`test-cases.md` のテストが通っている
- 性能の目標を、合成データ（全体で 10 万行・50 ブック）で測って満たしている。計測の値が `dev-notes.md` に残っている
- 実物の Excel で保存したブックで、読み込み・検査・保存後の反映を人が確かめている
