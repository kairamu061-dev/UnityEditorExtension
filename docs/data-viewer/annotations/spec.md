# annotations 仕様

## 機能一覧

| # | 機能名 | 説明 | テストケース |
|---|--------|------|------------|
| 1 | 補助情報の集まり | 名前の付いた「値 → 名前（と任意の説明）」の対応。値は整数か文字列 | U-01 |
| 2 | 組み込みの CSV | プロジェクトの中の CSV（`value,label[,note]`、1 行目は見出し）を 1 つの集まりとして読む | U-02, U-03 |
| 3 | 利用者が書く受け取り方 | `IAnnotationProvider` を Editor のアセンブリで実装すると、集まりの一覧に出る（ローカライズの表から名前を引くなど） | U-04 |
| 4 | 主キーへの結び付け | 集まりをテーブルの主キーに結び付ける。**その主キーを指す参照の列にも、同じ名前が出る**（`CharacterAbility.character_id` にもキャラクター名が出る） | U-05 |
| 5 | 列への結び付け | 集まりを特定の列（テーブル, 列）に結び付ける。参照ではない区分の値（`attribute = 1` → 「炎」など）に使う | U-06 |
| 6 | 検索 | 「名前も検索する」のチェックボックスがオンのとき、名前も検索の対象にする（「Claude」で `character_id = 1` の行が当たる）。既定はオン。オンかオフかが一目で分かる形にする（検証 1 で、ボタン型の切り替えは分かりにくかった）。結果の件数の横に「値と名前を検索」「値だけを検索」と出す | U-07 |
| 7 | 名前のない値 | 対応にない値は、名前なしで値だけを出す。問題にはしない | U-08 |
| 8 | 読み直し | CSV が再インポートされたとき、利用者の受け取り方が変更を知らせたときに読み直す | I-01 |

## 表示の仕方

**A（セルの中に並べる）に決めた**（検証 1、2026-11-13）。名前は括弧で囲む: `1（Claude）`。行の詳細も同じ書き方にする。

検証 1 で見比べた候補と結果:

| 候補 | 見え方 | 良いところ | 気になるところ |
|---|---|---|---|
| **A. セルの中に並べる（採用）** | `1（Claude）` | 一目で分かる。列が増えない | 列の幅が要る。値で並べ替えたいのか名前で並べ替えたいのかが曖昧になる |
| B. 隣に列を足す（次点。「捨てがたい」） | `character_id │ (名前)` の 2 列 | 名前で並べ替え・幅の調整ができる | 列が増える。参照の列が多いテーブルでは横に長くなる |
| C. ツールチップ（不採用） | セルは `1`。マウスを載せると `Claude` | 表が今のまま | 一覧で見比べられない |
| D. 行の詳細だけ（不採用） | 一覧は `1`。右の詳細で `character_id: 1（Claude）` | 表が今のまま | 一覧からは分からない |

- 行の詳細には名前を出す
- 切り替えは持たない（A だけにする）。B が欲しくなったら、列ごとの切り替えとして改めて考える
- 説明（CSV の `note`）はツールチップで出す

## エラーケース

| 条件 | メッセージ / 挙動 |
|------|------------------|
| CSV の同じ値が 2 行 | 問題にし、最初の行を使う |
| 結び付けの先（テーブル・列）がデータにない | 問題にし、その結び付けを無視する（settings の食い違いと同じ扱い） |
| 値の型が合わない（集まりは文字列、列は整数など） | 問題にし、その結び付けを無視する |
