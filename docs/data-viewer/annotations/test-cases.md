# annotations テストケース

## ユニットテスト

| ID | テスト名 | 入力 / 条件 | 期待結果 | ステータス |
|----|---------|------------|---------|-----------|
| U-01 | 集まり | 整数の値と文字列の値の集まり | それぞれ引ける。ない値は引けない | [ ] |
| U-02 | CSV | 見出しあり、`1,Claude`・`2,"Opus, the 5th",note`（カンマを含む引用）・空行 | 2 件。引用の中のカンマを保つ | [ ] |
| U-03 | CSV の重複 | 同じ値が 2 行 | 問題 1 件、最初の行を使う | [ ] |
| U-04 | 利用者の受け取り方 | テストのアセンブリに `IAnnotationProvider` の実装 | その集まりが一覧に出る | [ ] |
| U-05 | 主キーへの結び付け | Character の主キーに結び付け。CharacterAbility.character_id → Character | Character の主キーの列と、CharacterAbility.character_id の両方に名前が出る | [ ] |
| U-06 | 列への結び付け | Character.attribute に結び付け | その列だけに名前が出る。対照: 同じ値の別の列には出ない | [ ] |
| U-07 | 名前の検索 | `Claude` で検索 | `character_id = 1` の行が当たる（検索の対象にすると決めた場合） | [ ] |
| U-08 | 名前のない値 | 対応にない値 | 名前なし。問題は 0 件 | [ ] |

## E2Eテスト

|----|---------|---------|------|---------|------|-----------|
| — | 表示の仕方が決まってから書く | — | — | — | — | — |

## ステータス凡例

- `[ ]` 未実施
- `[~]` 実施中
- `[x]` 合格
- `[!]` 不合格
- `—` 対象外（差し替え・撤去など。理由を添える）

## 判定の注意

<!-- ここは消さずに残す。実際に判定を誤らせた形だけを書いてある -->

- **`0` を期待する項目には対照を置く。**「出なかった」は、**安定していた**のと
  **そもそも通っていない**のと区別が付かない。`1` になる場面を隣に置くか、
  数えている文字列が**実行ファイルの中にあること**を確かめる
- **「無いこと」を見る項目は、探し方が当たっているかを先に確かめる。**
  同じ探し方で「ある」ものを 1 つ挙げる。パスを間違えていれば、
  前も後も「無い」と出て、確認そのものが空になる
- **強い測り方に書き換える。**「見えていた」で通した項目は、次の回で弱いまま戻る。
  画素・ハッシュ・窓ハンドルで測れたなら、**その手順をここに書き写す**
- **1 つの操作を複数の窓口から見ている項目は、そう書く。**
  独立した N 件ではないので、「N 件通った」と数えない
