# data-viewer 概要

パッケージ: `com.obelune.data-viewer`（名前空間 `Obelune.DataViewer`）

## 目的・背景

ゲームのデータ（キャラクター・アビリティなど）を、C# の型で作ったリレーショナルなデータベースとして持つ。データは Excel などから変換して作り、次のような形をとる。

```csharp
class DataContainer {
    CharacterData characterData;               // class CharacterData { List<Data> data; }  Data = { character_id, attribute, power, … }
    CharacterAbilityData characterAbilityData; // Data = { character_id, ability_id }（中間のテーブル）
    AbilityData abilityData;                   // Data = { ability_id, evaluator, effect, … }
}
```

テーブルは ID で参照し合い、行は最終的に万単位になる。Inspector では、数万要素の `List` を開くと重く、参照先の行を辿ることも、参照切れに気づくこともできない。

この機能は、こうしたデータベースを、Unity エディタの中で**素早く参照・検索・検査**できるようにする。

## スコープ

### 作るもの

- データの入れ物（ルート）を受け取る仕組み。アセットを指定する組み込みのソースと、利用者が書くソース
- ルートから `List<T>` / `T[]` をたどってテーブルにし、列ごとの配列に取り出す処理
- 主キーとテーブル同士の関係（参照）を指定する設定と、その設定を編集する画面
- テーブル・行の一覧、検索、参照先へのジャンプ、参照元の一覧を備えた EditorWindow
- 参照切れ・主キーの重複・設定とデータの型の食い違いを一覧にする検査
- 規模の目標を測るための、合成データの生成と所要時間の計測

### 作らないもの

- 値の編集（正本は変換のもと。エディタでは参照だけ）
- Excel などからデータベースへの変換
- ランタイム（ビルドしたゲーム）で使う機能（`docs/project_overview.md` の方針どおり）
- データの型への属性の付与を求めること（パッケージにランタイムのアセンブリを持たないため。関係はすべて設定に書く）

## 制約

- データの入れ物の形（ScriptableObject のアセットか、独自のファイルから組み立てるか）は利用者がまだ決めていない。どちらでも使えるようにする
- ユーザーの型はリフレクションで読む。10 万行 × 10 列を `FieldInfo.GetValue` で読むと約 270 ms、式木でコンパイルした取り出しで int の 8 列が約 12 ms（**測った**。`dev-notes.md`）。列ごとの配列に取り出してから使う
- 開発用プロジェクトのアセットはテキスト（YAML）で保存される設定（`EditorSettings.asset` の `m_SerializationMode: 2`）。10 万行の ScriptableObject を読み込む時間は測っていない
- 規模とレスポンスの目標（`spec.md` の「性能の目標」）を満たすこと

## 完了条件

- `spec.md` の機能一覧のすべてについて、`test-cases.md` のテストが通っている
- 性能の目標を、合成データ（全体で 10 万行）で測って満たしている。計測の値が `dev-notes.md` に残っている
