# extract 仕様

決まりは [`../spec.md` の「データの決まり」](../spec.md#データの決まり) にある。ここには、その決まりの解釈を書く。

## 機能一覧

| # | 機能名 | 説明 | テストケース |
|---|--------|------|------------|
| 1 | たどるフィールド | `public` と `[SerializeField]`。`[NonSerialized]`・`static`・`const`・プロパティは除く。基底クラスのフィールドも含める | U-01 |
| 2 | テーブル | `List<T>` / `T[]` で、`T` がフィールドを持つ struct / class | U-02 |
| 3 | たどり方 | 4 段まで。同じオブジェクトを 2 度たどらない（循環しても止まる）。null のフィールドは飛ばす | U-03 |
| 4 | テーブルの名前と識別 | `../spec.md` の規則。名前が重なればパスで区別 | U-04 |
| 5 | 列の型 | 整数（`int`・`long`・`short`・`byte`・`uint`）→ `long[]`、`float`・`double` → `double[]`、`bool`、`string` → 文字列表の番号、`enum` → 数値と名前の両方 | U-05, U-06 |
| 6 | 入れ子の展開 | 行の中の struct / class は `親.子` の列として 2 段まで | U-07 |
| 7 | 行の中の配列 | 要素の数の列にする | U-08 |
| 8 | その他の型 | `ToString()` の文字列。null は値なし | U-09 |
| 9 | 表示と検索の派生データ | 全部の列について、表示の文字列（文字列表の番号）を作る。文字列表の小文字の写しを作る | U-10 |

## エラーケース

| 条件 | メッセージ / 挙動 |
|------|------------------|
| 行の型が取り出せない（式木を作れない型） | そのテーブルを問題として報告し、ほかのテーブルは取り出す |
| 行が null（class の行） | 値なしの行として数える |
