# data-viewer テストケース

個々のテストケースはサブ項目にある（`spec.md` の機能一覧から引ける）。ここには、全体を通して確かめるものだけを置く。

|----|---------|------------|---------|-----------|
| — | なし（サブ項目にある） | — | — | — |

## E2Eテスト

| ID | テスト名 | 前提条件 | 手順 | 期待結果 | 対照 | ステータス |
|----|---------|---------|------|---------|------|-----------|
| E-01 | 実際のデータでの通し | 利用者の DataContainer（またはそれに近い形のもの）。参照切れを 1 つ仕込む | ソースを選ぶ → 主キーと参照を設定する → 参照を辿る → 問題を確かめる → データを直して変換し直す | 行数・参照・問題がデータと一致。変換し直すと自動で読み直され、問題が 0 になる | 直す前に問題が 1 件出ていること | [ ] |
| E-02 | 利用側プロジェクトへの導入 | まっさらな Unity 6000.3 のプロジェクト | git URL でパッケージを入れる | コンパイルエラーなし。ウィンドウが開く | 無し（確認のみ。依存の規則を端から端まで確かめる唯一の場所。`docs/testing.md`） | [ ] |

## ステータス凡例

- `[ ]` 未実施
- `[~]` 実施中
- `[x]` 合格
- `[!]` 不合格
- `—` 対象外（差し替え・撤去など。理由を添える）

## 判定の注意

<!-- ここは消さずに残す。実際に判定を誤らせた形だけを書いてある -->

- **`0` を期待する項目には対照を置く。**「出なかった」は、**安定していた**のと
  **そもそも通っていない**のと区別が付かない。`1` になる場面を隣に置くか、
  数えている文字列が**実行ファイルの中にあること**を確かめる
- **「無いこと」を見る項目は、探し方が当たっているかを先に確かめる。**
  同じ探し方で「ある」ものを 1 つ挙げる。パスを間違えていれば、
  前も後も「無い」と出て、確認そのものが空になる
- **強い測り方に書き換える。**「見えていた」で通した項目は、次の回で弱いまま戻る。
  画素・ハッシュ・窓ハンドルで測れたなら、**その手順をここに書き写す**
- **1 つの操作を複数の窓口から見ている項目は、そう書く。**
  独立した N 件ではないので、「N 件通った」と数えない
