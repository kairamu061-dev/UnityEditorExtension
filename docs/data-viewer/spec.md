## データの決まり

### テーブル

- ルートから**フィールド**をたどる。たどるのは Unity がシリアライズするフィールドと同じ: `public` のフィールドと `[SerializeField]` の付いたフィールド。`[NonSerialized]`・`static`・`const`・プロパティはたどらない。**エディタは、実際に保存されているものだけを見せる**
- フィールドの型が `List<T>` か `T[]` で、`T` がフィールドを持つ struct か class なら、それをテーブルにする（`T` の 1 要素が 1 行）
- たどる深さは、ルートから 4 段まで。同じオブジェクトを 2 度たどらない
- **テーブルの名前**: そのテーブルを持つオブジェクトにテーブルが 1 つだけなら、そのオブジェクトの型の名前から末尾の `Data`・`Collection`・`Table` を除いたもの（`CharacterData { List<Data> data }` → `Character`）。2 つ以上あれば `型名.フィールド名`。名前が重なれば、ルートからのパスで区別する
- **テーブルの識別**: ルートからのフィールドのパス（`characterData.data`）。設定はこのパスで書く

### 列

- 行の型 `T` のフィールドを、テーブルと同じ規則で列にする
- 列の型: `int`・`long`・`short`・`byte`・`uint`・`float`・`double`・`bool`・`string`・`enum`（名前で見せる）
- 行の中の struct / class のフィールドは、`親.子` の名前の列として 2 段まで展開する
- 行の中の配列・`List` は、要素の数だけを見せる（検索と参照の対象にしない）
- それ以外の型（`UnityEngine.Object` の参照・ベクトルなど）は、`ToString()` の文字列で見せる（**推測**: 取り出しが遅くなる。fixtures で測る）

### 主キーと参照（設定で指定する）

- 主キーは、テーブルごとに 1 列を設定する。型は整数・`string`・`enum`。設定のないテーブルも見られるが、参照先にはできない
- 参照は「テーブル A の列 x → テーブル B」と設定する。x の型は B の主キーと同じ種類（整数どうし・`string` どうし）
- 参照ごとに「参照なしとみなす値」を設定できる（例: `0`）。その値は参照切れに数えない
- **候補を自動で決めることはしない**。設定の画面は、選べる候補（テーブル・列の一覧）を出すだけ

## 性能の目標

規模: 全体で 10 万行・テーブル 50 個・1 テーブル最大 2 万行（列は 1 テーブル 10〜30 列）。

| 操作 | 目標 | 測り方 |
|---|---|---|
| ウィンドウを開いてから、テーブルの一覧と最初のテーブルが出るまで（ドメインリロードの直後。アセットの読み込みを含む） | 0.5 秒以内 | fixtures I-03 |
| 検索の 1 打鍵ごとに、結果の表示が更新されるまで | 50 ms 以内 | fixtures I-03 |
| 参照先へのジャンプ（クリックから表示まで） | 16 ms 以内（1 フレーム） | fixtures I-05 |
| データが変わってから表示が更新されるまで（読み直し） | 1 秒以内 | fixtures I-06 |

アセットの読み込みが目標を超えるときは、ビューアの側でなく、データの持ち方（アセットを分ける・バイナリで保存する）で解決する（`dev-notes.md`）。

## 画面・操作フロー

1. `Tools/Obelune/Data Viewer` でウィンドウを開く
2. 初回はソースが未設定であることが表示される。アセットか、利用者が書いたソースを選ぶ
3. テーブルの一覧が出る。主キーと参照が未設定なら、設定の画面への案内が出る
4. 設定の画面で、テーブルごとに主キーの列を選び、参照を足す
5. 左のテーブルを選ぶと、中央に行の一覧が出る。行を選ぶと、右に詳細が出る
6. 参照の値をクリックすると、参照先のテーブルのその行に移る。「戻る」で元の行に戻る
7. 検索欄に文字を入れると、行の一覧がその文字を含む行に絞られる
8. 問題の数をクリックすると問題の一覧が出る。問題を選ぶと、その行か設定の画面に移る
9. 変換し直してアセットが再インポートされると、自動で読み直す

## 各画面 / 状態の詳細

### テーブル一覧（左）

- **表示内容**: テーブルの名前と行数。問題があるテーブルには数を出す。最下部に問題の合計
- **操作**: テーブルを選ぶ
- **遷移先**: 中央の行の一覧

### 行の一覧（中央）

- **表示内容**: 列名と型を見出しに出す。主キーの列に印。参照の列は値の横に参照先の最初の `string` 列を添える。参照切れのセルは目立たせる
- **操作**: 行を選ぶ。列の見出しで並べ替え
- **遷移先**: 右の行の詳細

### 行の詳細（右）

- **表示内容**: 全列の値。参照先（クリックできる）。参照元のテーブルごとの件数と、その行の一覧
- **操作**: 参照先・参照元をクリックしてその行に移る。「戻る」「進む」
- **遷移先**: 移った先のテーブルの行

### 設定

- **表示内容**: ソース。テーブルごとの主キー。参照の一覧（テーブル・列・参照先・参照なしとみなす値）。設定とデータの食い違い
- **操作**: 候補から選ぶ・参照を足す・消す。変えるとすぐ索引を作り直す
- **遷移先**: なし

## エラーケース

| 条件 | メッセージ / 挙動 |
|------|------------------|
| ソースが未設定・指定のアセットがない | 案内とソースの選択を出す |
| ソースがルートを返さない・例外を出す | 例外の内容を状態の表示に出し、前回の内容を出し続ける |
| 設定にあるテーブル・列がデータにない（フィールドの名前を変えたなど） | 問題として報告する。その設定は無視する |
| 主キーと参照の列の型の種類が合わない | 問題として報告する。その参照は解決しない |
| テーブルが 1 つも見つからない | ルートの型の名前と、たどったフィールドの数を出す |

## 未対応ケース

- 複数の列を組み合わせた主キー
- 1 つのフィールドに複数の参照を持つ（`int[] ability_ids` など）。多対多は中間のテーブルで表す
- `Dictionary` のテーブル（Unity がシリアライズしないため）
- `[SerializeReference]` の多態なフィールド
- 複数のソースを同時に開くこと
