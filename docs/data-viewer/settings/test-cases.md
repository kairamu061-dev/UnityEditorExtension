# settings テストケース

## ユニットテスト

| ID | テスト名 | 入力 / 条件 | 期待結果 | ステータス |
|----|---------|------------|---------|-----------|
| U-01 | 主キーの保存 | 主キーを 3 つ設定して保存し、読み込む | 同じ設定。2 回保存してもファイルが同じバイト列 | [ ] |
| U-02 | 参照の保存 | 参照なしの値ありと、なしの参照 | 同じ設定 | [ ] |
| U-03 | テーブル・列がない | データの列 `character_id` を `chara_id` に変えたあとの設定 | 問題 1 件（列の名前とテーブルを含む）。対照: 変える前は 0 件 | [ ] |
| U-04 | 型の種類が合わない | `int` の列 → `string` の主キー | 問題 1 件。その参照は解決しない | [ ] |
| U-05 | 参照先に主キーがない | 主キーのないテーブルへの参照 | 問題 1 件 | [ ] |

## E2Eテスト

| ID | テスト名 | 前提条件 | 手順 | 期待結果 | 対照 | ステータス |
|----|---------|---------|------|---------|------|-----------|
| E-01 | 設定の画面 | 例の DataContainer の形の合成データ。設定なし | 3 つの主キーと 2 つの参照を画面で設定する | 保存され、行の詳細に参照先・参照元が出る | 設定する前は、参照先・参照元が出ないこと | [ ] |

## ステータス凡例

- `[ ]` 未実施
- `[~]` 実施中
- `[x]` 合格
- `[!]` 不合格
- `—` 対象外（差し替え・撤去など。理由を添える）

## 判定の注意

<!-- ここは消さずに残す。実際に判定を誤らせた形だけを書いてある -->

- **`0` を期待する項目には対照を置く。**「出なかった」は、**安定していた**のと
  **そもそも通っていない**のと区別が付かない。`1` になる場面を隣に置くか、
  数えている文字列が**実行ファイルの中にあること**を確かめる
- **「無いこと」を見る項目は、探し方が当たっているかを先に確かめる。**
  同じ探し方で「ある」ものを 1 つ挙げる。パスを間違えていれば、
  前も後も「無い」と出て、確認そのものが空になる
- **強い測り方に書き換える。**「見えていた」で通した項目は、次の回で弱いまま戻る。
  画素・ハッシュ・窓ハンドルで測れたなら、**その手順をここに書き写す**
- **1 つの操作を複数の窓口から見ている項目は、そう書く。**
  独立した N 件ではないので、「N 件通った」と数えない
